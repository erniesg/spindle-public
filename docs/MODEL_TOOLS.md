# Optional remote-text suggestions and previews

`core/models/` implements typed application operations and a fixed-endpoint OpenAI-compatible text adapter for Nebius and NVIDIA hosted APIs. The preview now binds these operations to admitted captured evidence and explicit inspector actions through [capture classification](CAPTURE_CLASSIFICATION.md). It makes no request merely by constructing/opening the application or enabling capture. Local labels continue without a provider.

```sh
npm run build
node build/tools/model-demo.js
make check
```

The command is an explicitly **synthetic mocked demonstration**, not model inference, authenticated provider execution or a recommendation from real history. It performs no network/key lookup. Tests additionally exchange synthetic requests through real loopback HTTP mock servers; no paid endpoint is contacted.

## Application operations, not model authority

- `queryPermittedSummary(reader, {limit})`: at most 20 constructed summary rows from a pre-scoped authoritative local reader. It does not collect activity. The reader must enforce local permission/deletion before reading and supply deduplicated observed seconds; this module is not a second ledger.
- `ModelOperations.classify(labels, recordingId, visitId)`: suggest shared category/activity labels for already-admitted evidence. Exact user corrections/rules, conflicting rules and retired-rule abstention blockers are preserved without spending a call. Personal vocabulary, source IDs, raw URLs and images are not sent. Related concepts cannot be created or inferred by this adapter.
- `previewTimeLimit(reader, query, targets, targetId)`: propose a bounded time-limit **preview** tied to a chosen target revision and supplied summary evidence. No activate/apply/enforce operation exists.

`tool-schemas.ts` describes these application bindings with narrow JSON schemas. They are not an authenticated tool server or a model-driven dispatcher. The text adapter rejects provider-issued tool/function calls rather than running them. No arbitrary shell, file, network URL, lock, domain release, policy write, credit or payment tool is present.

The model receives a fixed system instruction and separately wrapped `untrustedData`. Page content never becomes system instructions. This is not a claim of model immunity to prompt injection: the enforceable boundary is strict output validation plus the absence of privileged effects. Proposals have `authority: none` and require a later independent user decision; model labels do not establish attention, study eligibility or desired goals.

## Independent consent and stale results

`RemoteConsent` starts local-only. An explicit application/user action must grant the exact provider/model, operation and named fields. Text classification permits only selected app/domain/title/text fields; it needs observed sampled content and permitted title/text with at least 24 characters and four letter-word groups. Rich classification additionally requires an explicit `image` grant, a vision declaration and the matching captured PNG. It can classify an image when OCR/text are empty; no text is invented and a missing requested image never silently becomes a text-only request. This conservative prototype gate rejects short/empty context; it is not semantic certainty and can abstain on other languages/formats. The model has an explicit `{decision: abstain}` output that leaves local labels unchanged. Recommendations separately require domain, observed seconds, span, coverage and the chosen target maximum. Source evidence IDs stay local: request-only aliases are mapped back after validation. Saved rules/vocabulary are not implicitly approved for egress.

Local text processing in `LocalLabels`, recording, Rich capture, retained images, local vision analysis and remote egress are separate. **On-device neural vision remains unsupported.** Remote images are now supported only by an explicitly declared vision model with verified token-only image accounting, a separate image-egress grant and the trusted capture binding. A Rich capture grant alone does not grant remote processing. No model operation activates a capture provider.

The application rechecks consent/evidence/catalogue/rules/corrections/deletion before dispatch and result application. Remote revoke aborts requests best-effort; source replacement, pause, correction and deletion reject late labels. History and chosen-target revisions fence recommendation results. A request already disclosed to a provider cannot be undisclosed by revocation; no immediate remote cancellation/deletion guarantee is claimed. The selected reader/target implementations remain responsible for actual local lifecycle enforcement.

## Bounded requests, prices and credentials

The adapter uses only:

- Nebius: `https://api.tokenfactory.nebius.com/v1/chat/completions`
- NVIDIA hosted NIM: `https://integrate.api.nvidia.com/v1/chat/completions`

Model IDs/capabilities/prices are **explicit operator declarations**, not discovered or authenticated by the library. There is no guessed default live model. Verify the account's actual model and JSON/text support, input context, output cap, token accounting and current input/output USD-per-million-token prices before constructing a live declaration. Pricing provenance is an HTTPS source plus verification time; shape validation is not proof the operator's numbers are correct. Unknown/image/extra billing units must not be used. Hosted NVIDIA/Nebius is remote, never an on-device model.

A Nebius declaration with `thinking:false` makes `TextProvider` and `NebiusAgentProvider` send `chat_template_kwargs:{enable_thinking:false}`. Without it, a hybrid reasoning model such as `nvidia/Nemotron-3.5-Super-VL` can spend the whole `max_tokens` on default reasoning and return no JSON. The control is included in the 8192-byte text-envelope check as well as the full request. Declarations that omit `thinking`, or set it to `true`, send the same body as before. `thinking:false` on NVIDIA is refused as `UNSUPPORTED_CAPABILITY` and is not silently dropped, because that wire control has not been verified there. The output ceiling, response validation and budget accounting are unchanged. The agent's bounded request and durable request envelope carry the same shared control without changing task IDs, token ceilings or accounting. The optional local `configuredNebius` loader does not accept the field yet. The regression in `tests/models/nebius-nonthinking.test.ts` checks only the captured offline transport body; it does not show that a live model returns a label.

Requests retain an 8192-byte text-envelope cap; vision adds at most one validated-header PNG (at most 2,000,000 encoded PNG bytes, each dimension at most 8192 and at most 33,554,432 pixels) as an inline data URL, never a model-selected external image URL. The full vision request is capped at 2,810,000 bytes. Output remains at most 512 tokens and time 15 seconds (10 seconds by default), including lazy credential lookup/transport/body reads. Input admission adds the declared conservative image-token upper bound; whole-context reservation remains mandatory. Capability/accounting declarations are operator responsibilities, not inferred from the filename or a successful mock. Input bytes plus a framing allowance must fit the declared context. Responses cap at 65536 bytes. Redirects, streaming, tool calls, malformed/truncated content and unsupported capabilities fail closed. There are no automatic retries or error-body/log exports.

A `CallBudget` is explicit per application session, with at most 100 calls and an owner-chosen USD limit. Each request reserves the whole declared input context plus bounded output at declared prices with 2× margin, conservatively rounded up to nano-USD; the ceiling rounds down. Valid reported usage reconciles that reservation. Failure or absent usage retains the full reservation; out-of-bounds accounting exhausts the session. This in-memory budget alone is not durable. The explicit preview Nebius binding uses `FileCallBudget` against an existing operator-selected cumulative journal, with exclusive mutation locks, in-place writes/file fsync, retained uncertain reservations and no automatic file creation/reset. Torn/corrupt writes and stale locks fail closed rather than resuming spending. Missing/corrupt/contended journals fail closed before credentials/network. Filesystem durability and native-platform behavior still require affected-host checks; this is not a provider billing API.

Credentials are loaded lazily by a trusted callback only after consent and budget admission. The library does not search stores, log keys or include them in model prompts/config digests. Only the explicit operator-configured preview binding lazily reads `NEBIUS_API_KEY`, after consent/current-source/budget checks; no UI/model-supplied key or credential-file path exists. Keep live keys outside source/UI/diagnostics; do not supply upload/deployment credentials. Injected transports are for trusted application/test bindings, never model-selected endpoints.

## Recommendations need real evidence

A preview requires at least seven days of selected history, at least 80% coverage, one hour of relevant observed time, and an observed per-day amount above the user's chosen maximum. These are conservative prototype eligibility gates, not native capture measurement budgets or proof that a proposed limit will help. No positive recommendation is produced from a ten-second run or unknown/partial history.

Only supplied, target-domain evidence IDs may appear in the preview. Minutes must lie between 5 and the chosen maximum; domain/target cannot be changed by model output. Explanatory basis and observed average are constructed by the application, not free-form unsupported savings/intent claims. All summaries are already-deduplicated observed person-time; the adapter neither multiplies confidence nor sums concurrent devices itself.

## Separate connected-agent provider (partial)

`NebiusAgentProvider` in `agent-provider.ts` implements the separate `AgentProvider` seam. It uses the fixed Nebius endpoint, an explicit caller-selected model/pricing declaration, lazy credential callback and default `fetch` (injectable for trusted tests). Strict `next_action` JSON selects one registered operation, a bounded batch (one to four calls), or a ready result. A batch uses `{"kind":"batch","calls":[{"callId":"unique-provider-ID","name":"registered tool","args":{}}]}`. Native `tool_calls` responses retain each original provider ID in the same batch contract. Duplicate, reused, oversized and malformed IDs/calls are rejected; the existing single-tool JSON interface remains available. Registered input/output schemas, durable task decisions and actual observations including runtime call IDs are supplied on subsequent turns. Arguments still pass through the runtime's registered schema parser before execution. The runtime validates every batch argument and checklist dependency, refuses external writes unless a trusted host supplies a narrow revision/argument-bound approval hook, and atomically reserves the entire cumulative tool-call budget before invoking anything. Trusted tool implementations continue to enforce source/grant scope; model arguments never add permissions. Only all-read batches without checklist bindings overlap (maximum four). Any write or checklist-bound batch serializes; after a non-successful operation in a write batch the remaining calls return explicit not-run errors. Actual results and failures retain their IDs and reach the subsequent model request in request order, even when completion order differs.

Omitted native `tool_calls` metadata or a genuinely empty array permits the existing strict `next_action` JSON content parser. Wrong-type metadata, malformed/nonempty invalid calls and oversized batches still fail closed without falling back to content; valid nonempty native calls take priority and preserve provider IDs. The sanitized actual-response regression uses an injected **offline** transport and an invented temporary budget journal to check parsed decision, durable request/response and usage settlement. It is not a new live call, saved/peer memory, model-quality evidence or live acceptance; the retained empty array proves a sufficient rejection cause, not the absence of other unretained raw-field defects.

Batch durability reuses the existing `Task.pending` fence without a storage migration: the durable decision records all calls; a single aggregate pending marker is `read` for pure reads, otherwise `external_write` if any admitted external write is present, or `write_local`. All observations commit together only while the run/application revision remains current. A crash with any possible local or external write requires explicit reconciliation, never automatic replay; interrupted pure reads may be explicitly recovered. Cancellation cannot commit late results. This conservative first slice does not recover partially completed batch observations individually or infer dependencies from model text; dependent calls should be separate turns.

Public catalogue research on 26 October 2026 found `nvidia/Nemotron-3.5-Super-VL` advertised with function calling at [Nebius models_info](https://tokenfactory.nebius.com/api/public/models_info); [the function-calling guide](https://docs.tokenfactory.nebius.com/ai-models-inference/function-calling) documents the API route. Neither catalogue advertising nor the scripted local HTTP regression proves this exact account/model emits multiple calls. This adapter uses structured JSON requests and also accepts native call responses; live native request negotiation and exact-model parallel capability remain unproven. No paid probe was made. Evidence is explicitly untrusted; it cannot confer grants or external-write authority.

The caller supplies an existing `FileCallBudget` and a `persist` callback that must durably commit each request envelope before dispatch and its concise decision/usage after response. Missing usage/failures retain reservations; no retry or fallback exists. The callback receives model/config identity, reservation ID, exact model-visible request and decision, never credentials or hidden reasoning. A crash between response persistence and settlement conservatively retains the reservation. `new AgentSessionStore(evidenceStore.db).persist` is an available durable callback using the context SQLite connection. Envelopes are keyed by workspace/account/task/run/cursor/reservation; completed responses are immutable and namespace-scoped readback survives restart. Use the same existing task budget journal across restart; the helper does not create/reset it. Request persistence, HTTP dispatch and journal settlement are not one atomic transaction: interrupted calls retain conservative reservations and must not be blindly replayed. Trusted application startup configuration is documented in [AGENT_STARTUP.md](AGENT_STARTUP.md); source wiring does not establish live conversation acceptance.

Caller cancellation, timeout and optional `isCurrent` checks fence adapter results. The runtime supplies its active signal, current-run predicate and task turn budget through the backwards-compatible optional third `ProviderContext` argument. The adapter combines these with its configured hooks and rechecks after credential lookup, so cancelling a pending lookup cannot later dispatch. Non-success HTTP bodies are cancelled without reading/exporting error text. Tests use a real local HTTP mock and an actual registered file read, not live inference. Actual account/model capability, multimodal input, live pricing and model-to-tool acceptance remain pending configured credentials and authorised live verification. No model availability is inferred from an ID or mock result. Existing classification behavior is unchanged.

## Live proof remains separate

Live calls require applicable scoped authorisation, verified actual-provider capabilities/pricing and the existing cumulative budget journal. Configuration and past unused allowance are not permission to spend, buy credits or replay a closed experiment. Current source-bound provider/scenario results and their proof limits belong in [#24](https://github.com/erniesg/spindle/issues/24), [#41](https://github.com/erniesg/spindle/issues/41) and the implementing PRs.

Mock/loopback tests do not establish hosted function-calling capability, on-device evaluation, real-history recommendation quality or installed capture-to-model behaviour. Keep synthetic, real-provider, native and installed evidence distinct.
