# Integrated Windows / Mac capture PREVIEW

**A limited test candidate, not full installed acceptance.** One shared TypeScript visit/control/encrypted-readback owner consumes native Swift/C# and a Chrome companion. No Linux recording product is implemented. [#30/#33](https://github.com/erniesg/spindle/pull/30) contain later source-bound Mac/Windows native results; historical unrun statements below refer to their named revisions, not a claim that no native test has ever passed.

The next [account-linked tracker milestone](PRODUCT.md#accepted-account-linked-tracking-milestone) is different from this preview: Rich selected by default after explicit consent, automatic matching screenshots, durable account-linked Mac/Windows history and labelled extended-session review (#66/#67 under #14). The preview now includes optional automatic browser Rich, encrypted persistent enrollment/preferences and OS-key retrieval on launch, always paused. Narrow app support and the 100-visit/15-minute local snapshot remain limits; account history uses the separate durable sink. This document describes the existing preview, not an implementation or acceptance claim for the new milestone.

**Important policy correction:** explicitly allowed, provenance-verified supported native windows can yield pixels/OCR/Rich **including content being edited**, independently of read-only/edit-state/recognized AX/UIA image layouts ([owner direction](https://github.com/erniesg/spindle/pull/33#issuecomment-6385078156)). Optional structured text extraction may skip editable/password/unknown subtrees without blocking window acquisition. Screenshots/OCR include visible edited content, sensitive fields and chrome; they are **not masked or image-only crops**. Use only invented content and explicit scope/exclusions. Supported families remain Mac system TextEdit/Preview/Finder/run-owned fixture and Windows verified Photos/Notepad/Paint Store families, existing OS-path families and run-owned fixture—not all apps or name-only admission. Source-bound native results and failures belong in [the implementation PR](https://github.com/erniesg/spindle/pull/33); no historical run validates these new bytes. Browser Default URL-origin/title/visible DOM source is implemented. Browser Rich supports manual activeTab and explicitly enabled automatic screenshots on enrolled ordinary pages, including editing and shadow surfaces. Embedded/iframe documents, oversized or changing documents remain unavailable. Structured extraction still excludes form/editable/hidden content; consented pixels include visible edited values and chrome, without masking. This is limited support, not complete browser Rich. Do not call all Default/Rich tracks complete.

In Basic, Windows Photos requests window OCR and other supported families use text completeness as the fallback hint. Optional bounded text scans use 180 nodes/depth 8 and 120 ms; their errors do not gate acquisition. Clearing/reopening fixture windows keeps ownership of the replacement process when an older child's exit/error arrives; Quit stops that current fixture. These safeguards do not replace native lifecycle verification.

Every optional Windows stage rechecks its cancellation lease and live foreground/process identity, including before UIA, WGC creation/frame copy, pixel access, OCR, encoding and transport. Windows sample diagnostics distinguish unavailable window/DPI, memory budget, window-frame acquisition failure, geometry change, OCR engine/language/empty/failed recognition, and retained-image encoding. Capture, OCR and image outcomes are shown independently. Titles refresh on the existing visit through the same epoch/revision/time/lifecycle fences; a same-window document change does not fabricate a new app visit. ## Storage and privacy boundaries

Windows WGC framePTS is raw compositor QPC time in milliseconds; sample.at is that time mapped to the native process stopwatch using its QPC origin. Do not subtract raw framePTS from process-relative visit times. Both OCR and retained PNG use that same frame. A no-new-frame interval does not manufacture a newer sample timestamp. The v1 preview protocol is an integration contract, not the production freeze in #2. Native producer monotonic clock IDs/timestamps and stream/epoch/focus revisions remain distinct from ScreenCaptureKit frame PTS and browser receipt estimates. Extraction never advances the native visit clock. Native A→B→A creates separate visits. A detected observation stall stops capture and marks a gap; no missed history is reconstructed. Unknown native/browser association is unavailable.

The shared AES-256-GCM store writes one bounded encrypted snapshot, including images and metadata, via encrypted staging + rename. No plaintext context/WAL/temp/log fallback. The existing OS helper creates/retrieves protected key material on launch while recording remains paused; this does not grant recording, retention or upload consent. Key failure blocks retention. The labelled synthetic store test injects a test key—it does **not** prove OS key access. Latest context expires after 15 minutes; readback removes expired records, and the encrypted file becomes unreadable after its deadline. When the process is off, physical expiry cleanup is lazy on subsequent read/write; no background startup service or forensic SSD-erasure claim.

Limits: 100 in-memory visits, 4096 text characters/result, about 6 MB aggregate base64 images, 8 MB encrypted snapshot, two outstanding storage writes, native pixel/OCR one-at-a-time. Busy optional work is dropped, not an excuse to merge visits. Native field availability is visible in each card; this is a conservative preview, not a frozen performance/coverage budget. OS idle/sleep/resource/permission and ordinary-app privacy acceptance remain pending. All launches restart paused. Enrollment and native app/pixel/Rich/retention choices persist encrypted for up to ten years; the key is retrieved through the existing OS helper, never copied into settings. `/state` exposes `settingsReady` and `preferences`; using those preferences still requires an explicit `/start`. Sign-in never starts recording. Rich grants no local vision model or remote inference; no model/network integration is called.

## Stop and remove

### Windows storage durability

Encrypted files are flushed before replacement on all platforms. The parent
directory is also synced on POSIX. Node's directory `fsync` is unsupported on
Windows, so Windows omits that directory barrier while retaining file flushing,
encrypted staging, replacement and explicit deletion. Ordinary restart/readback
is supported; survival of rename/deletion across abrupt power loss is not
guaranteed. File write, file flush, rename and deletion failures still fail the
operation; they are not treated as unsupported directory flushing.

Pause/Clear/Quit, close the inspector, remove the unpacked extension, then explicitly unregister the exact run-owned host **before moving/deleting the folder**:

- Mac: `bash "Enroll Browser.command" EXTENSION_ID --remove`
- Windows: `"Enroll Browser.cmd" EXTENSION_ID --remove`

The installer refuses conflicting manifests; Mac removal verifies the exact extension registration, package source/fingerprint, installation receipt and every installed byte before removing that fingerprint's runtime. Changed or unowned files and other fingerprints are preserved as conflicts. Pause/Clear/Quit stop capture but do not unregister or remove the installed browser host; run the explicit removal command before discarding the original package. Windows registration/removal behavior is unchanged. Remove the extracted candidate and its `.local` build logs. Local encrypted data/connection files live in `~/Library/Application Support/SpindlePreview` on Mac or `%LOCALAPPDATA%\SpindlePreview` on Windows. After Quit, remove that dedicated folder to remove remaining encrypted copies/DPAPI key. Mac's explicitly created Keychain generic-password item uses service `ai.berlayar.spindle.preview`, account `context-v1`; remove that specific item deliberately with Keychain Access if uninstalling. Remove only permission grants this test added and does not share.
