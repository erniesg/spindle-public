# Model-callable browser form tools (partial #50)

`createBrowserFormTools(options)` in `core/tools/browser-forms.ts` returns ordinary `ToolDefinition[]`: `browser.inspect`, `browser.fill`, `browser.upload`, `browser.submit`, and `browser.verify_submission` (matching issue #50's tool family). These are reusable tools, not a portal script. A model can inspect actual labels, types, options, requirements and actions, then select opaque refs and values from those observations. There is no expected-answer map in the module.

**Acceptance boundary:** the runtime rejects `external_write` without its narrow trusted `approveExternalWrite` hook. Fill, upload and submit retain that classification. The task binding below now tests actual normal-runtime writes, durable reviewed-revision authorization and the confined host with a scripted invented provider. Startup/owner-review integration and actual-model acceptance remain separate; no Google call or external-site submission was run. Never relabel writes as local/read to bypass the fence.

## Model interface

| Tool | Exact arguments | Result |
| --- | --- | --- |
| `browser.inspect` | `{}` | Snapshot ref, observed page requirements, fields with opaque refs/labels/types/options/constraints, submit actions with refs and observed form targets. No entry values. |
| `browser.fill` | `{snapshotRef, fieldRef, value}` | Hash-bound dispatched action, not a promise of no network effects. Text uses strings, checkboxes/radios booleans (radio selection only), selects exact option values or arrays for multiple-select. |
| `browser.upload` | `{snapshotRef, fieldRef, artifactId}` | Real `setInputFiles` with integrity-checked bytes, MIME and host-reviewed filename. No model path or URL. |
| `browser.submit` | `{snapshotRef, actionRef}` | One dispatch attempt after durable host intent claim; `dispatched` still requires verification. |
| `browser.verify_submission` | `{}` | Navigate to the host intent's exact receipt URL and revisit it; require matching persisted receipt evidence both times. No POST. |

Schemas reject extra keys, including selectors, JavaScript, paths, URLs and alleged grants. Observed refs are not authority. Unsupported or stale targets return `needs_input` with a specific recovery code. No automatic fill/upload/click retry follows uncertainty.

## Trusted host contract — required, not supplied by compilation

The factory never launches a browser, discovers profiles/credentials, installs Chromium, exports cookies, enumerates unrelated tabs or accepts arbitrary evaluation/navigation commands. The host supplies one owned Playwright `Page` and remains responsible for its lifecycle. Use a fresh explicitly admitted context, not the user's default browser profile.

`BrowserFormOptions` is the exported TypeScript integration seam:

- **`session(context)`** returns the actual current owned page/session ID, exact canonical destination and current `ApplicationRevisionRef` when one exists. Read-only inspection may precede application creation/approval; every write requires a real revision and separate valid host capability. It must reflect live host state, not echo model arguments or a stale task snapshot. Namespace/task scope and `ToolContext.applicationRevision`, cancellation and `isCurrent()` are rechecked around asynchronous work.
- **`constrained(session, context)`** attests that actual browser/context/transport enforcement is installed. Returning true is **not** that enforcement. Inspection and verification require a genuinely read-confined context; an apparently read-only GET/page load can execute scripts or cause writes.
- **`authorize(request, context)`** grants a revocable lease for the exact operation, session, destination, target, reviewed revision and `inputHash`. `request.input` contains transient actual value/field metadata, immutable upload identity/name/MIME/hash, or observed form state including submitter name/value. The host must compare it to the displayed authorized revision and permitted auxiliary fields. Scope lineage alone does not authorize sending an attachment. Do not persist/log raw request input or derive authority from page/model text. One valid submission instruction can cover every operation lease in that revision; these checks do not require another generic UI approval per upload/click.
- **`lease.isCurrent()` / `lease.close(outcome)`** enforce revocation and transport cutoff. Cancellation, deadlines and late grants must revoke actual queued/in-flight transport, not merely return an error. The module closes a late grant without dispatching. Failed cutoff quarantines this factory (`TRANSPORT_CUTOFF_FAILED`). Re-expose tools only after real host repair. Delayed autosave/background work remains constrained after `close`; dropping a temporary route must not open unrestricted networking.
- **`uploadName(artifact, context)`** supplies the reviewed filename. Separators/control characters and traversal names are rejected; the observed accept filter is checked. Names are not model filesystem paths. `resolveInput` enforces current namespaced source lineage and `EvidenceStore.read` verifies exact bytes/hash, with the existing 8 MiB input bound.

**Transport must restrict actual requests, not just the final page URL.** Enforce allowed origin/path/method, payload/attachment identity, request counts, redirects, frames, popups, service workers, WebSockets, downloads and background traffic. A page script may autosave on fill, change payload in a submit handler, or issue another request between DOM checks. DOM checks are not an atomic browser/network transaction. Admission and the lease must constrain those effects to the reviewed revision. The module must not be exposed to unscoped live pages until the host can enforce this contract.

A real Chromium finding in the fixture: `route.continue()` allowed transparent lower-layer replay after a lost POST response. A single tool invocation or click does **not** mean a single transport POST. The fixture host dispatches via `route.fetch({maxRetries:0,maxRedirects:0})`, validates the actual multipart body against the saved authorized content digest, then fulfills/aborts the browser request. Production must enforce its equivalent, plus applicable destination idempotency/reconciliation. This module makes no universal exactly-once claim.

## Durable intent and receipt adapters

`submissions.claim(request, context)` must use the **existing host-owned authorization/intent**, not mint approval because a model asked to submit. Atomically persist it and irrevocably claim dispatch before returning `{intent, dispatch:true}`. The returned intent binds session, destination, reviewed revision, actual input hash and an explicit same-origin exact receipt URL. Its durable state is already `uncertain` before dispatch: a crash at any later point must never automatically replay the POST. Repeated/restarted/concurrent claims return `dispatch:false`. All writes refuse an existing current intent and direct the caller to reconciliation. A genuinely new reviewed attempt is a host policy decision, not a model reset flag.

`submissions.current(context)` resolves only this task/account/workspace's current intent. `submissions.record(intent, state, context)` durably fences state transitions against current task/revision/revocation in the host transaction. These callbacks must observe cancellation themselves; pre/post checks cannot replace atomic host persistence. The host must persist the reviewed content evidence needed to validate a receipt across process restart.

`readReceipt(page, intent, context)` is the deliberately small site-specific part. Parse the actual navigated persisted record, compare its identity and submitted content/attachments with that intent's reviewed evidence, and return `{receiptId, contentHash, destination, revision}` only if established. A click, toast, HTTP 200, or parser that simply returns the expected revision proves nothing. `contentHash` is a SHA-256 of the persisted receipt content; receipt IDs must be noncredential references. The module requires two successful exact-URL navigations with identical parser results. It records a normalized receipt observation, not a full HTML/body snapshot. Failed/missing/changed/unbound receipts remain uncertain; verification never retries POST.

The fictional portal's parser in the test is a fixture adapter: receipt identity comes from its documented submission identity, and the content digest is derived from the actual authorized form state (not fixed answers). On response loss, the fixture host quarantines/closes the failed page and supplies a clean owned page within the same scoped session for receipt reconciliation. This avoids pending error-page navigation racing the read. The host still owns real restart/session recovery.

## Currentness, evidence and limits

Inspection reuses `BrowserPageInspector` and `WebReader`; their [existing extraction/authentication/privacy limits](WEB_TOOLS.md) remain. Additional form/action metadata and opaque refs bind to actual element/document handles. Re-inspection replaces the one current snapshot. Before effects, requirement/target fingerprints, actual element identity, destination, session, namespace/task, revision and capability are rechecked, including after authorization/intent persistence. Duplicate indistinguishable submit actions fail explicitly. Actual form values/file hashes are read transiently for submission authorization; normal inspect never reads them. Password controls require host/operator authentication and are never fillable through these tools.

Snapshots preserve source versions and actual observed metadata. Hash-only action-intent/effect records link back to source/artifact evidence, with input/output hashes and hashed lease identity; no raw fill values, uploaded bytes or driver exceptions enter those audit records. Uploaded artifacts already exist in the scoped EvidenceStore. Normalized verified receipt records have web-source provenance, destination/receipt binding and visit count. Host callbacks must not log credentials or put signed/credential-bearing URLs into these records. Hashing is not encryption or a claim that low-entropy inputs are anonymous. The existing EvidenceStore is not claimed encrypted.

Implementation limits, not product restrictions: ordinary main-document HTML form controls and submit actions; no cross-origin/alternate-window submission, iframe/shadow-DOM controls, custom canvas/rich editors or arbitrary SPA action interpretation. Submission requires an observed POST form. One immutable artifact is set per upload call. Extraction/collection bounds fail closed (1,000 controls, existing inspector field/material budgets, bounded action labels). A whole-tool deadline and per-driver bounds apply; the host owns actual browser teardown. Expected dynamic DOM changes after a fill/upload can conservatively return `WRITE_UNCERTAIN`: reconcile possible effects and inspect the new requirements rather than repeat blindly. Closing the owned page/context releases retained handles.

## Confined host adapter

`createBrowserFormHost(config)` in `core/tools/browser-form-host.ts` creates/owns a fresh context and one Page on an operator-owned Browser. Register `createBrowserFormTools(host.options)` normally after trusted `host.open(context)`; close the host to release its context, not the shared Browser. Fixed configuration binds account/workspace/task/session, destination, submission URL and exact read URLs. The existing durable submission callbacks and site-specific receipt parser remain host-injected, not a second ledger or universal parser.

`authorize` returns `{lease, signal, post?}`. The signal must abort on real capability/revision/account/session revocation or expiry. Optional `post` is one exact trusted `{url, encoding, fields, files}` allowance; files identify scoped immutable artifacts plus reviewed filenames. It must come from reviewed application authority, not simply echo model/page values. Submission URL writes additionally require the current durable claim; fill/upload cannot use that endpoint. Native form values normalize HTML line endings to CRLF and untouched empty file placeholders to omission; actual file bytes, MIME, names, field multiplicity and values are checked before dispatch. Outbound form framing comes from approved bytes, preventing hidden multipart/header channels. Each allowance is consumed before one retry/redirect-disabled transport POST. Deferred/post-lease requests remain denied.

The adapter routes HTTP(S) requests with exact URL/method/body/count and owned-main-frame checks, strips page-controlled headers/referrers/cookies, blocks WebSockets/downloads/extra frames/popups/workers, disables additional worker/WebRTC/WebTransport/deferred-fetch entry points, and applies restrictive response policy. Reads are explicitly admitted, not assumed effect-free. Read redirects are refused. Because Playwright does not re-route every URL in an HTTP redirect chain, only an intent-validated POST 303 is translated to a fresh routed receipt GET. Cancellation/revocation/uncertainty terminally quarantines the context and disposes/drains actual client fetches. A recipient may still commit after client shutdown; `status().lastPost === 'unknown'` is not remote rollback or proof of exactly-once delivery. Recreate a host with the coordinator's stable binding and trusted existing intent to reconcile, never re-POST.

Current adapter support is cookie-free main-document native multipart/URL-encoded forms, not authenticated profiles, arbitrary JSON APIs or an OS/network firewall against browser vulnerabilities. The operator owns Browser sandboxing and teardown. Request/response bounds are not a universal browser-memory guarantee. The task adapter below supplies durable state and narrow normal-runtime hooks; startup/owner-review integration and actual-model selection remain separate. `tests/tools/browser-form-host.test.ts` uses sandbox-enabled existing Chromium, invented loopback records and a scripted normal-runtime inspect round trip; it is not live-model/external-site/Mac acceptance. Run that compiled test serially with a short run-owned scratch `TMPDIR` (Chromium's Unix socket path limit applies), Node heap 256 MiB and compiler heap 512 MiB. The earlier 47-test result is historical evidence for the unchanged tool seam, not a new host rerun.

## Task-bound normal-runtime integration

`await createTaskBrowserTools(options)` in `core/agent/browser-host.ts` returns ordinary delegated `tools`, `execution: {approveExternalWrite, assertReady}`, trusted `approve(review, requestId)` / `revoke(approvalId)`, `close()` and `status()`. No approval/recovery-reset tool is model-callable. The sole shared type addition is `Task.browser`; approval bindings, write facts, pre-dispatch claims and receipts live in the existing atomic AgentStore Task JSON, with immutable reviewed content/attachment identity and receipt evidence in EvidenceStore. No new ledger/database/outbox is created. All actual browser behavior remains delegated to the form tools and confined transport above.

Trusted configuration binds task/account/workspace/session/destinations, an actual owner-authority `id`, revocation `signal` and currentness fence. Owner `approve` binds the current `Task.applicationRevision`, exact reviewed control names/optional observed IDs and values, native post fields/artifacts/filenames and receipt URL. These are independent reviewed inputs, not echoes of model/current DOM answers. Opaque refs must resolve against actual inspect results. One Submit instruction covers fill/upload/submit; non-submit network writes are denied unless `review.effects` explicitly supplies an exact approved plan. A real signal, not polling `isCurrent`, must cut off changed owner/session/revision authority.

Owner request identities are retained in versioned `Task.browser.approvalHistory`, with immutable bindings and monotone revoked/superseded dispositions. A duplicate returns retained facts, never replaces current authority or resets its signal; conflicting review/revision/authority/session/destination bindings fail closed. New request admission, prior supersession and current selection are atomic in the existing Task transaction, before review artifact creation, so same-ID retries add neither history nor artifacts. Request IDs are array values, not inherited object keys. Legacy state containing an approval/effect/claim but lacking this history cannot distinguish a valid current approval from one already revived by the old replay bug: new approvals and browser writes fail closed with unavailable history, while existing facts, inspection and honest receipt reconciliation remain available. Only pristine no-activity state can initialize history. This is lost-metadata recovery, not a new Google/browser consent requirement; no history or unknown claim is silently pruned/reset.

Wire **both** execution hooks into normal AgentRuntime options. Compose narrow family permissions by tool identity and run every relevant readiness gate; do not overwrite the mail/preparation gates. The host checks runtime pending/run/generation admission before any effect grant and atomically claims submission before POST. Browser-domain recovery survives the runtime clearing single-call `pending`: unknown fills/autosaves/submissions block new approval, further writes and Ready across store reopen or newer revisions. The adapter never clears/rewrites global Task pending/generation/budget/recovery; existing generic interrupted-run recovery remains coordinator-owned. A missing Ready hook is unsafe: the recorded RED baseline reached Ready after a real lost-response POST when that hook alone was omitted.

Receipt verification loads the original intent/review even after a newer Task revision, while fencing the actual current runtime. It does not authorize writes for that old revision or certify a newer revision. Two actual parser observations and immutable receipt evidence are committed before reporting verification; late cancellation/uncertainty cannot downgrade retained verified facts. Unknown non-submit autosaves need a genuine site-specific reconciliation path, not a new approval/reset. Current binding supports one submission claim per task; a later separately requested submission needs coordinator task/attempt handling without erasing this history. Ordinary unnamed controls need an explicit observed ID; ambiguous upload targets fail closed. These are implementation limits, not product restrictions.

`tests/agent/browser-host.test.ts` exercises normal external-write registry/runtime calls with scripted invented providers, two changed forms, real PDF bytes/server records/receipt revisits, exact approval denials, complete stores reopen after lost ACK, unknown autosave readiness holds and post-receipt-commit cancellation. This proves the task/transport path, **not LLM selection, normal startup/UI acceptance, live/private journey or native Mac execution**. Reuse the prior transport evidence for unchanged source; do not describe the historical 47/13 checks as rerun for this task delta.
