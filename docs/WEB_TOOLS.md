# Web requirements tools (partial #44)

`WebReader` resolves application-supplied opaque references, never a model URL. Production reads require HTTPS; explicitly configured exact numeric-loopback origins permit the fictional local portal. Redirects are bounded and rechecked against the original origin. Response bytes and time are bounded. Authentication and unavailable pages throw explicit failures. `webReadTool` supplies shared metadata/schema and checks runtime source/destination scope, cancellation and task currency. Snapshots preserve exact fetched bytes, original URL, retrieval time and SHA-256 as source version in the namespaced EvidenceStore. Page text never grants destinations or write authority.

`BrowserPageInspector` accepts an operator-owned Playwright-compatible page, observes ordinary visible labels, constraints, file accept types, descriptions, select options and visible text (including photo/deadline prose), and snapshots the actual observation. Navigation during inspection is stale, including path/query changes. Password controls, including hidden ones, require operator authentication. It does not read entry values, interpret prose as verified photo compliance, fill values, upload, or submit. Editable DOM text is excluded before text reads in both the body and label/description helpers, using inherited browser editability (including plaintext-only and nested readonly islands). Editable regions are still traversed for password refusal and extraction budgets; ordinary readonly requirements and field metadata remain available.

Extraction is incremental **inside the page, before IPC**, not a final Node-side slice. A depth-first walk replaces full `body.innerText`, `textContent` and eager descendant arrays. Text nodes are read in chunks of at most 256 UTF-16 units. Limits are 2,048 units per metadata value/combined label/description, 100,000 units of body text, 500 visible fields, 32 labels/description references per field, 500 options per select, and 20,000 visited nodes shared across the document and auxiliary label/description/option walks. Exact URL identity has an 8,192-unit limit; field IDs/names use the metadata limit. Oversized identities are rejected, never truncated.

A shared 512,000-byte conservative materialization/serialization allowance charges strings **before** chunk reads or inclusion (six bytes per UTF-16 unit plus overhead) and containers before construction. This can exhaust before an individual limit, depending on the page. Attributes are checked immediately on DOM API return, before trimming/splitting/concatenating. The walk holds only a bounded ancestor stack; collections are checked before iteration. These are extraction-work/intermediate/output limits, **not a universal browser-memory guarantee**: the operator-loaded DOM, DOM API internals, layout, page scripts and browser serialization machinery are outside that claim.

Any exhausted budget throws an explicit incomplete-scan error. No partial observation is returned or persisted as authoritative requirements, and an incomplete scan cannot certify password absence. Cancellation/deadline and exact navigation checks still fence persistence; late evaluation cannot save a snapshot. The trusted operator continues to own browser/context teardown (a rejected evaluation race does not terminate page JavaScript). Successful snapshots retain the exact URL and existing provenance shape; visible text remains an observation, not verified compliance.

Browser driver installation/context lifecycle is **not bundled**: the operator supplies a compatible page, browser binary and scoped navigation. The inspector does not itself navigate or constrain browser subresources. A registered `browser.inspect` now exists in the browser form tools (see BROWSER_FORM_TOOLS.md) over a confined host, but no registered `browser.open` or hardened read-only navigation adapter exists; do not expose a general browser to untrusted model navigation on the strength of this seam.

`TavilySearch` calls only the fixed HTTPS search endpoint with an explicit lazy credential callback, five-result maximum, bounded response, cancellation and no fallback. Returned URL hashes identify actual search results but do not grant navigation authority. Search sources still require trusted admission and authoritative page reads. A registered search envelope/provenance snapshot and live provider acceptance remain pending. No paid/provider call was made for this change.

## Focused checks

```
npm run build
npm run typecheck
SPINDLE_WEB_CHROMIUM=/operator/path/to/chrome node --max-old-space-size=256 --test --test-concurrency=1 build/tests/tools/web*.test.js
```

Browser checks require the explicit executable above; without it they skip, which is not browser acceptance. They use actual Chromium and invented local HTTP pages: changed ordinary labels/constraints, eager-getter guards, oversized labels/descriptions/attributes/options/identities, collection and measured traversal/materialization exhaustion, late/hidden passwords, navigation, cancellation/deadlines and no late persistence. HTTP and credential regressions remain included. This is read-only web requirements machinery, not capture/recording or native UI: no capture visuals apply. It is not Gmail/model/connected-journey or live search acceptance. Independent review, the complete browser adapter and live search acceptance remain open.
