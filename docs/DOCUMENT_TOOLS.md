# Local PDF document tools (partial #47)

`createDocumentTools(EvidenceStore)` exposes inspect, fillable-field edit, generic flat-page text overlay, render, text extraction and explicit flattened export through the existing registered tool contract. Inputs are opaque scoped source/artifact IDs resolved through immutable evidence storage, not paths or URLs. Each write publishes one derived PDF, retaining the original and source lineage; output metadata includes input/output hashes and operation parameters. Normal tool observations must be durably retained by the runtime for full operation provenance.

Operations require `document.processing`, current task authority and active cancellation. The child process receives no provider credentials, has a 256MiB heap and 15-second deadline, and bounds input/output and PDF graph traversal. Known automatic/action-bearing content and encryption are rejected; benign dictionary `A` keys and passive URI links are not blanket-rejected. This is not a general PDF sanitiser or sandbox guarantee.

Text edits preserve positive template default-appearance font size and reject measured overflow rather than silently shrinking. By default this slice uses Helvetica. Unsupported glyphs and missing/automatic font sizes fail without publishing output. An operator may configure an optional licensed rendering font (below). This is an implementation limitation, not a product-wide ASCII policy. Password values are redacted from discovery and cannot be edited/exported. Validation returns `data.issues` with a stable code, bounded field name when applicable, and plain next action. Codes distinguish unknown/type/unsupported fields, overflow, unsupported glyphs, unsupported PDFs/fonts, and missing required fields. Parser exceptions, supplied field values and operator paths are not included in these issues. Existing consumers can continue using status/error and metadata. Missing required fields remain visible even when an edit successfully creates a partial PDF; success is not completeness. Failed operations publish no PDF and do not remove originals or previous versions.

## Capability-first inspection (partial #47)

Inspection now includes `metadata.editingCapabilities`: discovered supported non-readonly, non-password text/checkbox/selection field names, `fieldEditing` (`supported` or `unsupported`), `overlay` (`supported` on safe unsigned noncredential PDFs, otherwise `unsupported`), `signedSource`, and `credentialFieldsPresent`. This is source capability discovery, not validation that a proposed value, glyph or appearance will fit. Ordinary nonfillable/image-only PDFs retain empty fields; no fields or overlay coordinates are invented. An AcroForm edit with no supported fields still fails `no_editable_fields` without publishing an artifact; explicit generic overlays do not need field names. Signed sources remain immutably inspectable/readable, but modification is refused; this is not signature verification. Credential-bearing forms expose no password values and credential fields are never editable.

The owner-selected actual form is not yet available in this worktree. Application attachment propagation (#48), semantic field grounding/correction, native packaging and real connected acceptance remain outside this PDF slice. Invented fillable/flat samples prove generic operations, not actual-form fit or NAC acceptance.

## Generic overlay and actual render geometry

`document.overlay({inputId, pageIndex, coordinateSpace, placements})` creates one derived PDF without changing its source. `pageIndex` is zero-based. Each placement is `{type:'text', box:{x,y,width,height}, value, fontSize}`: literal text, an explicit positive bounded box, and font size in physical PDF points (1–144). There are 1–128 placements and at most 4096 characters per value, within the existing 32 KiB argument envelope. No template coordinates, field names or values are baked in. Text is measured with the selected font, including line height/descent; unsupported glyphs, controls, overflow and off-page boxes fail with typed issues and no publication. There is no shrinking, erasure, signature drawing or source overwrite. Overlaying a signed, signature-field, encrypted, action-bearing or credential-bearing PDF is refused. AcroForm edits continue using their existing discovery/type/readonly/required-field checks.

Coordinate space is explicit:

- `{kind:'page_points'}`: displayed visible CropBox after source page rotation, top-left origin, x right/y down, physical PDF points (1/72 inch, including actual UserUnit).
- `{kind:'render_pixels', imageArtifactId}`: the exact PNG returned by `document.render` for this input/page. Boxes use top-left full-image pixels, but font size remains physical points. The tool resolves the image in the current namespace/granted lineage, re-renders the exact PDF/page with the configured renderer and compares image hash and direct input lineage. It derives the conversion itself, not from model-supplied dimensions or matrices. Re-render after a source/renderer change. Cropped/resized OCR images must first map back to this full image using the OCR canonical transform; their coordinates cannot be passed as if full-image pixels.

`document.render({inputId,pageIndex})` returns a derived PNG plus `data.metadata.render`. The existing `document.export({inputId,format:'png',pageIndex})` returns the same geometry. Metadata includes actual `pageIndex`, exact PDF `sourceHash`, PNG `imageHash`, `mediaBox`, visible `cropBox` (CropBox intersect MediaBox), `rotation`, `userUnit`, displayed `pagePoints`, actual PNG `pixelDimensions`, `coordinateSystem`, `scale`, `pdfToPage`, `pdfToImage` and `pageToImage`. Matrices use `[a,b,c,d,e,f]`: `x'=a*x+c*y+e`, `y'=b*x+d*y+f`. PDF-user-space input is unrotated bottom-left; image output is rotated visible crop top-left. Poppler uses fixed `-cropbox -scale-to 1600`; actual IHDR dimensions determine both scale axes, including rounding. `inspect.metadata.pages` carries the same parser-derived page geometry before rendering. Source/page geometry is not model-asserted; OCR boxes/text remain model estimates, not ground truth. No confidence or automatic semantic mapping/appearance quality is invented.

Render and text extraction publish local derived artifacts, so they now declare `write_local` (only inspect is `read`). Expected input/worker validation failures are typed failed ToolResults with no artifacts. Once publication begins, storage and post-commit exceptions escape unchanged, even during concurrent cancellation, so AgentRuntime retains its write fence/reconciliation path instead of accepting phantom success. Operation parameters, resolved point placements and geometry live in normal ToolResults/task observations; no shared evidence schema/store extension is needed.

The input bound is the existing worker's **8 MiB PDF**, not a 512000-byte probe cap. Inspect exposes input/output 8 MiB, 100 pages, 256 fields, 128 placements, 12 MiB combined worker request/response and optional 4 MiB font bounds. Input plus base64 font/metadata must also fit that combined envelope. Worker and renderer have 15-second deadlines; worker heap is 256 MiB. These are implementation resource bounds, not a universal product file-size policy.

Observed pilot: five invented actual PDFs covering changed sizes, crop offsets, 0/90/180/270-degree rotations and licensed Unicode/UserUnit; real Poppler text bounding boxes match supplied visual placements, leading zeroes survive, and rendered/exported outputs differ while originals remain unchanged. All five PNGs were self-inspected, not independently approved. Final affected checks: 51 PDF tests passed with zero skips using configured Poppler/DejaVu; broader runtime/evidence/provider checks passed (121 pass total, four unrelated optional shared-memory-server integration skips). Typecheck/build used 512 MiB compiler heap, tests 256 MiB serial; 17 Python repository checks passed. Actual SQLite INSERT failures for every artifact-producing document operation retain Runtime reconciliation; injected post-commit/cancellation failures preserve the original error and committed bytes without phantom success. The >512000-byte ordinary-PDF case also succeeds. Encryption-marker refusal is a structural parser test, not proof of a cryptographic implementation. Retained proof and prior failures are under ignored `.local/pdf-overlay/`; no native UI changed, so no manufactured native recording is offered. No actual private input, live provider, Google upload, ordinary-user visual review or full #51 acceptance is established.

## Ordinary PDF text layers (partial #47)

`document.extract_text({inputId, pageIndex})` reads one zero-based page from a scoped immutable PDF, including non-form bank statements. Configure `pdftotextExecutable` with an absolute operator-owned Poppler path at tool creation; neither the model nor document content chooses executables, paths, arguments or grants. No new dependency/font is installed. The operation uses PDF stdin and UTF-8 stdout, with fixed `-layout` arguments. It returns literal text, input/output hashes, page index/count and a derived `text/plain` artifact with root-source evidence; AgentRuntime durably retains the ToolObservation. It does not overwrite or reserialize the original.

The existing bounded PDF inspection/active-content/namespace/hash/current-revision guards run before Poppler. Password-bearing forms are refused before launching it because plain-text previews cannot redact their values reliably. Signed PDFs may be read immutably; this is not signature validation and does not relax edit/export restrictions. Pages must be integers inside the actual PDF (maximum 100 pages).

The owned extractor has a 15-second deadline (`textDeadlineMs` may lower it through trusted factory configuration), 64 KiB stdout cap and 8 KiB stderr cap. Abort/deadline/overflow kills it and waits for close before returning; no generic process-tree or OS sandbox guarantee is claimed. The cap is checked on each buffer before retaining/decoding it. Strict UTF-8 decode rejects invalid bytes. Oversize returns `data.issues[].code = text_too_large`, without a partial artifact. Blank/scanned pages return failed `no_text_layer`, with an explicit render-page plus OCR fallback. Missing/unavailable configuration returns `text_extraction_unavailable`. These are not successful semantic reads.

Even below the stdout limit, Poppler layout/engine coverage is unverified: extracted text is evidence, not a guarantee that every visible glyph was recovered. `metadata.textLayerCoverage` explicitly says `unverified`, and `semanticVerification` is false. In an exploratory repeated-digit stress input, Poppler returned fewer characters than drawn; therefore no `completePage` or universal full-read claim is made. Use the source/render plus OCR when extraction is suspect. Model-backed OCR remains separately required for the connected journey; this tool is not its replacement.

Set `SPINDLE_DOCUMENT_TEST_PDFTOTEXT` and `SPINDLE_DOCUMENT_TEST_FONT` to trusted absolute installed paths to run the real backend tests; absent configuration is an explicit test skip, not a fake backend. The configured full suite passed 184 Node tests with zero skips and 16 Python checks; build used a 512 MiB compiler heap, Node tests 256 MiB serial. No package/Makefile changes were needed because the normal existing globs include `tests/tools/*.test.ts`.

Observed Linux Poppler 24.02.0 checks: ordinary non-form ASCII, embedded licensed DejaVu `Živa Ω` and `0098765`, blank text layer, actual oversized varied text, scope/hash/account/current refusal, immutable signed read and credential-preview refusal. Synthetic executable checks prove strict UTF-8 failure and owned-helper deadline/active-abort/reaping; **real Poppler cancellation is not claimed**. A scripted provider observes actual extraction through AgentRuntime and reopens task/source/artifact evidence. No external model/network, Windows/native UI or real Google acceptance is established. This shared backend API has no affected native interface to record; retained original PDF/text and local rendered PNG are the inspectable evidence instead of a manufactured UI demo.

## Optional operator-owned rendering font

```ts
createDocumentTools(store, {
  pdftoppmExecutable: '/absolute/operator/path/to/pdftoppm',
  renderFontPath: '/absolute/operator/path/to/DejaVuSans.ttf',
  renderFontLicense: 'Bitstream-Vera + DejaVu-public-domain',
});
```

These are trusted factory configuration, never model arguments, grants or input source IDs. Provision and license the font separately; no font binary is bundled or committed. The loader opens without FIFO blocking, checks a regular file no larger than 4 MiB before allocation, bounds its read and rejects growth/truncation. The font crosses only the bounded credential-free PDF worker request; the existing combined request/output limit and worker deadline still apply. The worker checks actual glyph coverage before measuring/setting each edited text or selection value, preserves the explicit template font size, measures widget space, and subset-embeds the font. Unchanged form fields retain their original appearances. Complex-script shaping, arbitrary fonts, CJK, universal PDF quality and Windows support are not proven by the Greek/extended-Latin example.

The successful edit's `data.renderAssets` records the font byte SHA-256, embedded font name and operator-supplied embedding-license identity. This is rendering provenance, **not factual field evidence**: no font SourceRef, authority or change to PDF source/artifact lineage is created. License identity is an operator assertion, not an automated legal check. Keep operation observations with the document version, and accompany distributed embedded-font outputs with the applicable notice.

For local synthetic checks set `SPINDLE_DOCUMENT_TEST_FONT` to the absolute operator font path and `SPINDLE_DOCUMENT_TEST_PDFTOPPM` to the installed renderer. They are test configuration, not product environment-path APIs. No font download, paid call or model probe occurs. The generated PDF/PNG and tool/runtime results are retained under ignored `.local/retained-pr47-validation`.
