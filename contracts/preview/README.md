# Capture integration PREVIEW v1

This is an explicitly unstable integration contract for `core/preview/`, not the production freeze or the draft Python reference. Both Windows and Mac adapters feed **one** TypeScript visit owner. It introduces no Linux capture target and does not adopt legacy code/data.

- Native bounded newline JSON uses `schema: spindle-native-preview/v1`. Commands: `key`, `start {epoch,apps,pixels,rich}`, `stop`, `quit`. No arbitrary command/file API. Native replies: `ready`, `capability {code}`, `clock`, `focus {epoch,revision,at,clock,key,app,title,browser}`, `sample {epoch,revision,at,text,textSource,status,image?,framePTS?,title?,capture?}`, `activity {epoch,at,inputAgeBucket}` (coarse age bucket only, no raw input stream), `gap`, `key` (private pipe only), `locked`, `error`. Unknown native versions stop the helper. Key bytes never reach HTTP, feedback, model prompts or disk plaintext.
- Windows `capture` optionally reports content-free `pixels`, `ocr`, `image` stage codes plus `sourceWidth/Height`, `imageWidth/Height`, and `ocrWidth/Height`. A 128 MiB bitmap backing allocation ceiling replaces fixed window dimensions. OCR copies are bounded to 4 million pixels and the OS engine maximum. PNG retention adaptively reduces the full-window image only when needed to fit the existing 2,000,000-byte ceiling; reduction is disclosed. OCR failure does not prevent Rich. Optional native sample titles refresh the existing visit only after the normal epoch/revision/time/lifecycle fences; Mac producers may omit the optional title/capture fields. Samples are atomic: missing text/image does not borrow older content. Rich supplies OCR and optional retained PNG from the same admitted Mac frame/Windows bitmap, never an older AX/UIA read. Mac suppresses AX-only updates over an active Rich stream. Basic prefers structured text; when pixels are unavailable, fresh scoped structured-text-only acquisition remains possible without pairing it with another frame. Existing local OS OCR is reused; actual native quality/performance acceptance is still required.
- Native `at` is process-incarnation monotonic milliseconds; `clock` is a fresh opaque producer clock ID. ScreenCaptureKit PTS is retained separately, never subtracted from this clock. Optional extraction does not advance boundaries. A return creates a new visit. Focus revision, epoch, current OS target and field permission fences reject late results; gaps stop rather than fabricate continuous coverage. Atomic explicit gap notifications (no intermediate Pause capture) revise overlapping durable intervals and tombstone later identities through the existing sink, including identities evicted from the preview ring; ordinary ring eviction never deletes durable history. Delayed authoritative native focus explicitly reconciles prior browser receipt-time identities before admission of the new native UUID; it cannot delete that new visit. Valid pre-boundary context/correction survives a timing-only edit, while late text/pixels clear. Retroactive invalidation advances the owner generation, fencing old Saved/restore copies. Bounded redacted current-recording templates retain interval/acquisition-time metadata only, not another clock/store. Independent image time participates even without newer DOM/heartbeat; closures reject later context and never extend an already closed interval. Valid pre-gap time/context/corrections remain; same-key exact-base bounded reconciliation in the existing encrypted pending state preserves evicted evidence after restart/paging, never blank-replacing an unresolved base. At most 64 such metadata intents may wait; deletion/expiry dominates. Only invalidated-context `coverage-gap` records have no retained context/acquisition metadata/frame/capture and no new browser DOM observation. Native events still have the documented pre-fsync crash window, not a lossless journal.
- Browser Native Messaging/IPC uses `schema: spindle-browser-preview/v1`, bounded request IDs and only `pair`, `challenge`, `context`, `image`, `revoke`. Browser-to-host/IPC requests are bounded to 3 MB for the optional image; replies remain small. `challenge` advertises `rich` only when pixel/retention/Rich controls are enabled; older peers without this capability deny image acquisition. Revocation fences in-flight extension work, persists a disabled/pending hashed token receipt and removes known local browser content with durable deletion intent before acknowledgement. Offline/restart/failure retries remain possible; completed old-token retries cannot revoke later enrollment. A pending restart reopens its account by explicit signin, not recording Start; pairing/Start stay held during cleanup. Local acknowledgement is not remote deletion completion: bounded sync must drain tombstones. Explicit user pairing returns a profile token persisted only in encrypted app settings and extension-local setup. The current-user filesystem/IPC secret is separate. Chrome allowlisted extension registration is explicit. This is not authentication against malicious code running as the same OS user.
- `context` includes an exact issued visit/epoch/revision/lifecycle challenge, ordinary/private=false and focused=true proof from Chrome APIs, document ID plus navigation generation, sanitized origin/title/bounded visible text. Unknown/private/unfocused/unpermitted states do not invoke the extractor. The helper suppresses **all** browser title/AX/OCR/pixels without native fallback. Browser time boundaries are conservative receipt estimates, labelled partial, not a validated cross-clock mapping or short-visit guarantee.
- Rich requires separate pixel + retention + Rich controls and an OS-protected key. Under the [owner-authorized policy correction](https://github.com/erniesg/spindle/pull/33#issuecomment-6385078156), native window pixels/OCR/Rich are independent of read-only, edit-state and recognized AX/UIA image layouts. The supported families remain Mac system TextEdit/Preview/Finder and the run-owned fixture; Windows live verified Photos, exact OS-path Explorer/Notepad/Paint and the run-owned fixture. Live process/provenance, explicit app allowlist, foreground/target/incarnation, pixel consent and cancellation fences remain mandatory. No arbitrary PID, name-only admission, native browser detail/pixels or monitor fallback. Structured text extraction skips password/editable/unknown subtrees; its failure or incomplete/chrome-only text requests OCR, not pixel denial. Authorized window screenshots/OCR can include visible edited content, sensitive fields and chrome; they are not masked or image-only crops. Explicit scope/exclusion and invented test content are essential. The removed policy is deferred to [separate issue #34](https://github.com/erniesg/spindle/issues/34), not a capture dependency, packaged module or auto-enabled filter.
- Mac reports Accessibility (`NATIVE_READY` / `ACCESSIBILITY_REQUIRED`) independently of Screen Recording (`SCREEN_RECORDING_GRANTED` / `SCREEN_RECORDING_REQUIRED`). Inspector state/feedback expose both capabilities, not an inference from AX readiness. Content-free sample statuses distinguish association, shareable-content and stream-acquisition failures. Windows uses a persistent window-only Windows.Graphics.Capture stream bound to the exact HWND, with lease and geometry checks and whole-window OCR. Frames from before the visit or older than 750 ms are rejected, and no rapid-visit coverage budget is accepted. Mac fences stream generation, worker identity, process/geometry association (exact focused-window title disambiguates colliding bounds; missing/duplicate titles remain unavailable), monotonic host PTS and current scope/target/permission before pixel-buffer access and processing/transport. Native calls already running cannot be interrupted; a 3-second worker watchdog fails the helper closed even when paused. These new bytes require affected native verification, not inferred acceptance.
- Browser `image` supports manual gesture fallback or explicit automatic-Rich opt-in. Automatic capture separately requests Chrome's optional `<all_urls>` screenshot capability; that capability never enrolls origins or starts recording. Both paths require the same admitted challenge/document/navigation/sanitized resource, ordinary/focused/enrolled state, explicit pixel/retention/Rich scope and bounded PNG/memory. Pixel consent includes visible edited fields and open/closed-shadow content, which is not masked; structured text continues to exclude sensitive/form/embedded subtrees. Pixel acquisition rejects embedded documents and revalidates document revision/navigation/focus/profile/permission/challenge around capture. Native browser AX/OCR/pixel fallback remains forbidden. Source/image receipt times are separate and late frames are rejected, not clamped. Browser coverage remains receipt-timed/partial, not a native foreground guarantee. Default never encodes/persists images. Readback decrypts the actual store, not category counts.
- Inspector `/state` snapshots and `/restore` replies expose the current owner's monotonic `generation`, not a generation trusted from a saved file. A changed owner generation invalidates both rendered Saved copies and in-flight restore responses; older responses cannot roll the client back. Owner disconnect/missing revision clears displayed context. This is polling-based UI propagation, not a zero-latency cross-window erasure guarantee.
- Stored snapshot `spindle-capture-preview/v1` is AES-256-GCM authenticated (nonce/tag and expiry/created header), bounded to 8 MB and two writes. Latest context has 15-minute expiry. Settings/snapshot commits fsync encrypted file → rename → directory, and clear/expiry unlink has a directory barrier; failed barriers do not acknowledge cleanup. Clear invalidates pending writes and fences old work. Restart is paused, with encrypted preferences/enrollment restored only after the OS-protected key is available; no automatic capture resume. Start/signin share exclusive control ownership across asynchronous work. A sink is published only after settings and lifecycle/key fences pass; canceled work detaches its sink. These are source/API durability contracts, not tested physical power-loss or Windows filesystem guarantees. Physical off-process expiry cleanup is lazy; no forensic erasure claim.

Safety ceilings (100 visits, 4096 text chars, 6 MB base64 image memory, 2 fps Mac stream, 500ms native extraction, 1s browser refresh) are preview bounds, **not accepted native budgets**. No attention or measured resource guarantee is supplied. Coarse input age is not absence; the optional account-history sink and shared cross-device session/overlap/correction APIs are documented in [TRACKING_API](../../docs/TRACKING_API.md), not another clock or ledger. Account browser viewing requires no collector enrollment/native installation/recording permission. Native/installed and whole presentation journeys remain unaccepted. [Candidate instructions and missing implementation](../../docs/CAPTURE_PREVIEW.md) own the runnable journey; native/installed acceptance still requires actual target tests under [TESTING](../../docs/TESTING.md).
